# Frontend structure

```
src/
├── app/                    Next.js App Router - routes only, thin
│   └── projects/[projectId]/
├── components/             Presentational components
└── lib/
    ├── api/
    │   ├── types.ts        GENERATED from backend contracts - do not edit
    │   ├── schema.json     GENERATED - the JSON Schema types.ts comes from
    │   └── client.ts       Typed fetch layer + job polling
    └── hooks/
        ├── useJobStream.ts  Live progress over SSE - the intended path
        └── useJob.ts        Polling - the fallback when a stream is not
                             available
```

## Rules

**Never hand-write a type that mirrors a backend spec.** `types.ts` is
generated by `npm run types` (which runs `scripts/generate_types.py`). A
duplicated interface drifts the moment a field is renamed, and the failure
shows up in the browser weeks later, far from the change that caused it.

**Everything slow is a job, and jobs stream.** Analysis and rendering take
minutes. The API returns a `job_id`; subscribe with `useJobStream`. Events are
named (`segment`, `shot`, `candidate`, `stage`), so a screen can show *what* is
happening rather than only a percentage - which is what makes a five-minute
wait feel like work instead of a hang.

`useJob` polls instead, and remains as a fallback. Prefer the stream.

**Reconnection is handled, but only because events are replayed.** Every event
carries a sequence id; `EventSource` sends the last one back on reconnect and
the server replays from there. A page reloaded mid-job catches up. Do not
"optimise" this by dropping the id.

**Surface every upload rejection.** Media validation is all-or-nothing and the
API returns a typed issue for every rejected file. Showing a generic success
while quietly dropping footage is not allowed.

**Read media readiness from the Asset API, not ProjectDoc.** Proxy and
thumbnail generation changes `uploaded / processing / ready / failed` state
without creating a creative edit. Poll `listProjectAssets` while work is
active so a page reload can recover the current durable state.

**Files are served by the API, never by a storage path.** Use `mediaUrl(key)`.
Storage keys are backend-internal and will stop being local paths as soon as
the backend moves to object storage.

## Regenerating types

```bash
npm run types        # from apps/web
```

Run it after a change to an exported backend contract or API response envelope.
